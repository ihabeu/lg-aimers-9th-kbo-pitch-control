# 대회 목적 및 규칙

**마지막 업데이트: 2026-08-14**

## 1. 대회가 왜 이 문제를 다루는가

야구에서 투수의 "제구력"은 실점 억제, 볼카운트 운영, 타자 대응 전략에 직접 영향을 주는 핵심 능력이다. 전통적으로는 평균자책점(ERA), 볼넷 수, 스트라이크 비율처럼 **경기가 끝난 뒤 집계하는 지표**로 제구력을 평가해왔다. 하지만 실제 경기 중에는 볼카운트, 주자 상황, 타자·투수의 특성, 그날까지의 컨디션(과거 이력) 등이 복합적으로 작용해서 "이번 한 공"의 제구 성공 여부가 달라진다.

이 대회는 결과가 나온 뒤의 통계가 아니라, **투구가 이루어지기 직전까지 확인 가능한 정보만으로 그 투구의 제구 성공 확률을 실시간으로 예측**하는 문제를 다룬다. 즉 "그 투수는 통산 얼마나 제구가 좋은가"가 아니라 "지금 이 순간, 이 상황에서, 이 공이 제구에 성공할 확률은 몇 퍼센트인가"를 맞히는 것이 목표다.

## 2. 대회 진행 단계

| 단계 | 내용 |
| --- | --- |
| Phase 1 | 교육과정 이수 조건. Phase 2 참가를 위한 사전 단계 |
| **Phase 2** (현재 진행 중) | 온라인 해커톤. 이 문서가 다루는 대회. 리더보드 상위 약 100명이 Phase 3 진출 |
| Phase 3 | 1박 2일 오프라인 해커톤. 세부 과제는 추후 안내되며, 온라인과 동일하게 야구 데이터 기반 AI 문제로 진행될 예정 |

Phase 2 참가 자체가 목적이 아니라, **Phase 3에 안전하게 진출할 수 있는 순위를 확보하는 것**이 이 프로젝트의 실질적 목표다.

## 3. 문제 정의

- **예측 단위**: 투구 1개(train.csv/test.csv의 행 1개 = 실제 투구 1개)
- **예측 대상**: `control_success` — 그 투구가 제구에 성공할 확률(0~1 사이 실수)
- **제구 성공/실패의 정의**: 공의 실제 위치를 기준으로, 아래 3가지 중 하나에 해당하면 **실패(0)**, 그 외 유효한 투구는 **성공(1)**
  1. 스트라이크존 가운데 부근으로 들어간 공
  2. 스트라이크존에서 크게 벗어난 공
  3. 포수의 요구 방향과 반대로 들어간 공

야구 규칙과 컬럼 의미에 대한 배경지식은 [`도메인.md`](도메인.md) 참고.

## 4. 데이터셋 구성

`data/` 폴더(원본 설명서: [`data/data_description.md`](../data/data_description.md))에 4개 파일이 있다.

| 파일 | 크기 | 역할 |
| --- | --- | --- |
| `train.csv` | 1,475,092행 × 49컬럼 | 학습용. 각 행이 투구 1개, 정답(`control_success`) 포함 |
| `test.csv` | 배포본 5행(형식 확인용) × 48컬럼 | 평가용. 실제 채점 시 서버가 245,789행 실데이터로 자동 교체. 정답 컬럼 없음 |
| `sample_submission.csv` | 5행 × 2컬럼 | 제출 양식(`row_id`, `control_success` 확률) |
| `trackman_history.csv` | 1,793,078행 × 30컬럼 | 2019~2024년 Trackman 물리 특성 참고 로그. train/test와 별도 ID 체계라 1:1로 안 붙음 |

**시간 축이 핵심이다**: train은 2019~2024시즌, **test는 2025시즌**(학습 데이터에 전혀 없는 미래)이다. 이 구조 때문에 데이터를 다루는 방식 전체(검증 방법, 최종 재학습 여부 등)가 결정된다 — 상세는 [`전처리 및 인사이트.md`](전처리%20및%20인사이트.md) 참고.

train/test 공통 입력 피처는 5개 그룹으로 구성된다(컬럼별 상세는 [`eda/COLUMNS.md`](eda/COLUMNS.md)).

- 기본 식별자/경기 정보: `row_id`, `season`, `game_month`, `game_dayofweek`, `inning`, `top_bottom`, `game_type`
- 투구 직전 카운트/점수: `balls_before`, `strikes_before`, `outs_before`, `run_top_before`, `run_bot_before`, `run_total_before`, `score_diff_home`, `score_diff_pitcher_team`
- 주자/상황 중요도: `runner_on_1b/2b/3b`, `num_runners_on`, `base_state`, `home/away_win_expectancy`, `li`
- 선수/팀: `pitcher_id`, `batter_id`, `pitcher_hand`, `batter_hand`, `pitcher_team_id`, `batter_team_id`
- 투구 직전까지의 과거 이력(`asof_*`): 투수/타자의 누적·최근경기·구종별 성공률 등 19개 사전계산 피처

## 5. 평가 지표 — Brier Skill Score

```
Score = max(0, 100000 × (1 - Brier / (r × (1 - r))))
Brier = mean((p_i - y_i)^2)
r = mean(y_i)   # 전체 평가 데이터의 실제 평균 제구 성공률, 비공개
```

- `p_i`: i번째 샘플에 대한 예측 확률
- `y_i`: i번째 샘플의 실제 정답(0 또는 1)
- `r(1-r)`은 "그냥 평균값 하나로 전부 찍었을 때"의 Brier(베이스라인). 이 값 대비 얼마나 개선했는지를 0~100000 스케일로 환산한 게 최종 점수
- 모델이 완벽하면 Brier=0 → Score=100000. 베이스라인과 동일하면 Score=0(그 이하는 0으로 clip)
- Brier는 확률의 **절대적인 정확도와 보정(calibration)**까지 같이 보는 지표라서, 단순히 순위만 잘 매기는 것(AUC 개선)만으로는 부족하고 확률값 자체가 실제 빈도와 잘 맞아야 한다.
- Public Score는 전체 평가 데이터 100% 기준이며, Private Score도 대회 종료 시점 기준 Public Score와 동일하게 계산된다(별도의 숨겨진 홀드아웃 분리가 없음).

체감상 Brier 0.0001 개선이 대략 점수 40점에 해당한다(이 프로젝트가 실측한 근사치).

## 6. 목표 및 평가 방식

- **Phase 2 수료 조건**: Phase 1 이수 + Phase 2 Public Score **549.51점 이상**(운영진 베이스라인 코드를 운영진 평가 환경에서 실행한 기준 점수)
- 1차 평가: 리더보드 Private Score 100% 기준 순위
- 2차 평가: Phase 3 진출을 희망하는 팀은 코드+PPT를 제출해 검증받아야 함. Private 상위 약 100명이 코드/PPT 검증까지 통과하면 Phase 3 진출

이 프로젝트의 목표는 수료 기준(549.51)을 훨씬 넘어, Phase 3 진출 순위를 안전하게 확보할 수 있는 고득점(현재 목표 1300점대)이다.

## 7. 제출 형식 (코드 제출 대회)

`submit.zip` 구조(최상위에 불필요한 폴더 없이 정확히 이 구조여야 함):

```
submit.zip
├── model/              # 모델 가중치
├── script.py           # 추론 코드 (제출 시 자동 실행)
└── requirements.txt    # 필요 패키지
```

- `script.py`는 평가 서버가 자동 마운트하는 `data/test.csv`(읽기전용)를 읽어서, `output/submission.csv`(컬럼: `row_id`, `control_success`)를 생성해야 한다.
- 데이터 경로가 규정 문서 안에서 구조도에는 `data/`, 유의사항 텍스트에는 `open/`으로 다르게 적혀 있어(오타로 추정) 이 프로젝트의 `script.py`는 두 경로를 모두 시도하도록 방어적으로 작성했다.

## 8. 실행 제약 조건

| 항목 | 제한 |
| --- | --- |
| 전체 추론 시간 | ≤ 10분 (245,789개 샘플 기준) |
| 패키지 설치 시간 | ≤ 10분 |
| 제출 파일 용량 | ≤ 10GB (압축 해제 후 ≤ 32GB) |
| 인터넷 연결 | 패키지 설치 단계만 가능, 이후 오프라인 |
| 서버 사양 | 6 vCPU, 28GB RAM, L4 GPU 22.4GiB VRAM |
| Python/CUDA | Python 3.11.15, CUDA 12.8 |

서버에 이미 설치된 주요 패키지(`torch==2.7.1+cu128`, `pandas==2.0.3`, `numpy==1.26.4`, `scipy==1.15.3`, `scikit-learn==1.8.0`, `transformers==4.46.3` 등)는 버전이 다르면 충돌 위험이 있어 `requirements.txt`에 안 넣는 걸 권장한다. `catboost`/`lightgbm`/`xgboost`/`joblib` 등은 서버에 사전 설치돼 있지 않으므로 반드시 `requirements.txt`에 명시해야 한다.

**패키지 버전 함정**: 설치 단계는 온라인이지만, 참조하는 PyPI 미러가 최신 버전을 항상 갖고 있지는 않다. 실제로 `xgboost==3.3.0`(당시 최신)이 설치 실패한 적이 있어, 정착된 지 오래된 구버전(`xgboost==2.1.4`, `lightgbm==4.5.0` 등)으로 낮춰 쓰는 걸 권장. 이때 로컬에서 학습에 쓴 버전과 제출 패키지에 명시한 설치 버전을 반드시 일치시켜야 한다(joblib pickle은 xgboost/lightgbm 메이저 버전 간 호환을 보장하지 않음).

**제출 오류 2종류**:

- 설치 오류: `submit.zip` 구조 불일치, 패키지 설치 실패 등. 일일 제출 횟수에 반영되지 않음
- 제출 오류: `script.py` 실행 중 발생하는 모든 오류. 일일 제출 횟수에 반영됨(무제한 재시도 불가)

## 9. 평가 데이터 사용 원칙 — 반드시 지켜야 하는 leak 방지 규정

평가 데이터의 **각 행은 독립적으로 예측**해야 한다. 평가 서버에서 `test.csv` 전체가 한 번에 주어지더라도, 다른 행을 이용해 현재 행의 피처를 만드는 것은 전부 금지된다.

금지되는 예시:

- `test.csv` 내부 행들을 이용한 선수별/팀별/월별 누적 통계
- `test.csv` 내부 빈도값 또는 분포 통계
- `test.csv` 내부 target encoding
- `test.csv` 행 순서 기반 rolling 또는 expanding feature
- 평가 데이터 전체를 보고 만든 사후 보정값(calibration을 test 분포로 fit하는 것도 금지)

운영 측이 제공한 `asof_*` 컬럼은 각 행의 투구 직전 시점까지의 과거 기록만으로 계산된 공식 입력 피처이므로 그대로 사용 가능하다.

## 10. 사용 금지 정보

공정한 평가를 위해 아래 정보는 입력으로 쓸 수 없다.

- 현재 투구 이후에 확정되는 모든 정보
- 현재 투구의 실제 위치/코스 정보
- 현재 투구의 실제 판정, 결과, 제구 성공 여부(타겟 그 자체)
- 현재 투구의 실제 구종
- 현재 투구의 Trackman 측정값
- 2025년 Trackman 데이터(제공되지 않음)
- 평가 데이터 내부의 다른 행을 이용해 만든 누적/빈도/분포/rolling/target encoding 피처

허용되는 것은 `train.csv`, 평가 환경의 `test.csv`, 2019~2024년 `trackman_history.csv`, 그리고 대회 규정상 허용되는 외부 데이터뿐이다.

## 11. 대회 공정성 규정 — 타 참가자 자료 취급

DACON 부정 제출 공지(다른 참가자들과의 형평성에 어긋나는 참가 방식 금지)에 따라, 이 프로젝트는 다음 원칙을 명시적으로 지킨다.

- **아이디어/방법론은 공개 자료를 참고할 수 있지만, 코드/구체적 수치/하이퍼파라미터를 그대로 재현하지 않는다.** 아이디어를 읽고 반드시 직접 코드를 새로 작성해서 검증한다.
- 이 원칙은 이 프로젝트가 실제로 위반한 뒤(다른 참가자의 실제 코드를 그대로 가져다 쓴 시도가 있었고, 실제 리더보드에서도 검증돼 한때 채택됐다가 자체적으로 발견해 철회함) 확립한 것이다. 관련 경위는 비공개 아카이브에서 관리하며, 이 저장소(공개)에는 상세 내용을 올리지 않는다.
- 같은 팀으로 병합될 예정이더라도, DACON에 공식 병합이 완료되기 전까지는 여전히 다른 팀으로 취급해 이 원칙을 그대로 적용한다.
