## 무엇을 예측하는가

KBO 야구 투구 하나하나(row 1개 = 투구 1개)에 대해, 그 투구가 "제구 성공"인지를 확률로 예측하는 이진분류 문제. 정답은 `control_success` (1=성공, 0=실패)이고, 아래 3가지 실패 케이스를 제외한 나머지가 성공으로 정의된다.

1. 스트라이크존 가운데 부근으로 들어간 공
2. 스트라이크존에서 크게 벗어난 공
3. 포수의 요구 방향과 반대로 들어간 공

투구 직전까지 알 수 있는 정보만 입력으로 써야 하고 (사후 정보, 실제 코스/판정/구종/현재 투구의 trackman 실측값은 전부 금지), 평가는 `Score = max(0, 100000 × (1 - Brier / (r(1-r))))` — Brier Score를 평균 제구율 기준 베이스라인 대비 얼마나 개선했는지로 채점한다.

## 이 데이터셋의 특징 (직접 확인한 것들)

**시간축 구조가 핵심 변수다.** train은 2019~2024, test는 **2025년**이다. 즉 학습 때 한 번도 못 본 시즌을 예측해야 한다. 실제로 연도별 성공률이 계속 떨어지고 있다.

| season | 성공률 | 표본 수 |
| --- | --- | --- |
| 2019 | 0.565 | 237,413 |
| 2020 | 0.533 | 244,087 |
| 2021 | 0.533 | 247,088 |
| 2022 | 0.529 | 247,472 |
| 2023 | 0.500 | 245,525 |
| 2024 | 0.486 | 253,507 |
| 2025 (test) | ? | 245,789 (비공개) |

2019→2024 사이 -7.86%p 하락. 랜덤 분할 CV를 쓰면 이 추세를 못 잡고 과최적화된다 — 시즌 순서를 지키는 rolling out-of-time(OOT) 검증이 필수인 이유.

**순간 상황 정보는 신호가 거의 없다.** 볼카운트, 아웃카운트, 주자상황, 이닝, 요일 등으로 쪼개봐도 성공률이 0.50~0.54 사이에서 거의 안 움직인다. RandomForest 변수 중요도에서도 이 컬럼들은 전부 하위권.

**투수/타자의 과거 이력(`asof_*`)이 진짜 신호다.** `asof_pitcher_success_rate`, `asof_pitcher_reverse_rate` 등이 변수 중요도 상위를 싹 쓸었다. 단, 결측 패턴이 두 종류로 나뉜다 — "완전 첫 투구"(0.05%)와 "최근 등판 이력 부족"(1.98%)은 원인이 달라서 같은 방식으로 채우면 안 된다.

**팀 단위 효과는 노이즈일 가능성이 높다.** `pitcher_team_id` 22/23번 성공률이 튀어 보였는데, 표본이 각각 676/4,437건뿐이라(다른 팀은 13만~21만건) 실제 효과인지 소표본 노이즈인지 구분이 필요하다.

**trackman_history는 당장 안 쓴다.** ID 체계가 달라 매핑 작업이 따로 필요하고, 매핑까지 해서 검증해봐도 성능 개선이 노이즈 수준이었다 (자세한 내용은 [eda/EDA.md](eda/EDA.md) 6절).

## 폴더 구조

```
모델링/
  README.md          # 이 문서
  eda/
    eda.py             # 스키마·함수 정의 (실제 로직, `python eda.py`로 단독 실행도 가능)
    eda.ipynb          # eda.py를 import해서 셀별로 실행 + 결과·의도 설명 (실행 결과 포함)
    EDA.md             # EDA 결과 해석 문서
    eda_outputs/       # 실행 결과 csv
  r_estimation.ipynb  # 리더보드 점수로 비공개 r(평균 제구율) 역추산하는 노트북
  modeling/
    baseline_catboost.py    # CatBoost 베이스라인 (결측치 전처리 없이 네이티브 처리)
    baseline_catboost.ipynb # 실행 결과: 2024 OOT 로컬 Score 734.49
    models/                 # 학습된 모델 가중치 (.cbm)
```

코드 작성 원칙: 실제 로직은 `.py`에 함수로 두고, `.ipynb`는 그 `.py`를 import해서 셀 단위로 실행하며 결과와 의도(마크다운)를 같이 남긴다. 로직 중복을 피하려고 `.ipynb`가 `.py`를 참조하는 방향으로 통일.
